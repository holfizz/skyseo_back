# Миграция подготовки созвонов

Дата: 13 октября 2026.

Финальный schema diff: `CrmLead.callPreparation CrmCallPreparation?`; новая модель `CrmCallPreparation` с уникальным `leadId`, FK на `crm_leads` (cascade при удалении самого лида), статусом/этапом/версией, JSON исследования и outline, двумя PDF, ошибкой, lease и датами. SQL: `prisma/migrations/20261013080000_call_preparations/migration.sql`.

План:

1. Проверить Prisma validate/generate и сборки. Прогнать HTTP/DB-контракты на отдельной локальной БД через Prisma Migrate; проверить права, конкурентные запросы, lease, повтор этапа и сохранение квалификации.
2. Коммит и push main локально. На сервере только `git pull --ff-only`, сборка и `docker compose up -d --no-build`; исходные файлы не редактировать.
3. Штатный старт backend запускает `prisma migrate deploy`. Миграция создает одну новую таблицу, FK и два индекса; существующие таблицы/данные не переписывает. `db push` запрещен.
4. Проверить примененную миграцию, состояние контейнеров, маршруты с авторизацией и наличие runtime assets.

Квалификация и прогресс остаются в CrmLead. Follow-up читается из CrmTask и сохраняется общим FollowUpService. Ни CrmLead, ни TgRecipient, ни legacy followUpAt/followUpNote не удаляются и не заменяются. На повторный клик у лида остается одна подготовка; сохраненные ответы не копируются в исследование.

При откате кода оставить добавленную таблицу: старый код ее не использует. Не удалять документы или исследования ради отката. Не создавать новые исследования автоматически для всех лидов.

Исторические миграции проекта не могут развернуть совершенно пустую БД: первая миграция ссылается на ранее существовавшую users. Для изолированных тестов создан временный baseline из schema HEAD и затем применена именно новая миграция через migrate deploy; история прод-миграций не менялась.
